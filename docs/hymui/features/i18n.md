# Internationalization Plan

> Status: planned foundation  
> Initial languages: English and German

## Goals

- English is the primary source language.
- German ships with the first development release.
- Language changes apply to the complete interface without a reload.
- No user-facing string is hard-coded inside a Vue component or API handler.
- Dates, times, numbers, lists, and relative times follow the active locale.
- Missing keys fall back to English and are reported during development.

## Package structure

```text
packages/i18n/
  src/
    locales/
      en/
      de/
    index.ts
    schema.ts
```

Messages are grouped by product domain rather than by page:

```text
common
navigation
projects
board
docs
planner
agents
settings
errors
```

The English message tree defines the typed key schema. CI rejects missing or
unknown German keys.

## Locale selection

Locale precedence:

1. explicit user preference
2. workspace default for signed-in users
3. saved device preference
4. browser language
5. English fallback

Local works without an account and stores the device preference locally.
Self-hosted and Hosted synchronize the signed-in user preference through the
API.

## Backend behavior

The frontend sends a locale with requests where localized output is required.
Stored domain data remains language-neutral. API error responses use stable
machine codes; the frontend translates those codes.

Emails, notifications, exports, and agent-generated UI summaries use the
recipient's effective locale. Audit events store stable codes and structured
parameters instead of translated sentences.

## Quality requirements

- pseudo-locale coverage for clipped layouts
- browser tests in English and German
- timezone-explicit Planner tests
- no string concatenation for translatable sentences
- pluralization through locale-aware message rules
- locale-aware sorting where users see ordered names or titles
